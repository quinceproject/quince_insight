# Quince Insight

**Google Analytics, Tag Manager, Merchant Center and Search Console in one place for PrestaShop 9.**

Quince Insight connects a PrestaShop shop to Google through one setup wizard and one
Google sign-in: Google Analytics 4, Google Tag Manager with Google Ads conversions,
Merchant Center, Search Console with a sitemap, Site Verification, page speed and
structured data. It is a connector, not a statistics tool: it sets the services up,
sends them the shop's data and tells you when something stops working.

> Quince Insight is a free, open-source module (OSL-3.0). There is nothing to buy.
> If it saves you time, you can support development, see
> [Supporting the project](#supporting-the-project).

## Features

- **One wizard, one sign-in.** Your own Google Cloud project, then a Google sign-in that
  asks only for the permissions of the services you chose, then one step per service.
  The wizard can be left and resumed, and any service can be connected later.
- **Nothing on the shop pages without your decision.** Installing the module changes
  nothing a visitor sees. The verification tag, the Tag Manager snippet, structured data
  and the Customer Reviews window are each switched on in the panel, with a description
  of what will be added.
- **Analytics.** The GA4 property and web stream are picked or created, together with the
  Measurement Protocol secret and the purchase key event. Reports for 7, 28 or 90 days
  with comparison: overview, traffic, and a purchase funnel counted by events or by
  visitors.
- **Tag Manager built for you.** The container content (data layer variables, triggers,
  the Google tag, GA4 event tags, Google Ads conversion, Conversion Linker and
  remarketing) is planned from the settings and compared with the container. You review
  the list of changes first; nothing is saved until **Apply and publish**. Publishing
  runs in the background within Google's request limits. Or keep your own container and
  let the module add only the snippet and the data layer.
- **E-commerce events from shop data.** Fifteen GA4 events built in PHP from the shop's
  data, not read from theme HTML, with Consent Mode v2 defaults and Quince CMP as the
  consent source when it is installed.
- **Purchases and refunds from the server.** Through the Measurement Protocol, with
  partial refunds and protection against counting a purchase twice. The module never
  invents a visitor identifier: an order without a GA session or without consent is
  logged with the reason instead of being sent. Missing orders are sent automatically
  within the window in which they still keep their traffic source.
- **Merchant Center.** Account, developer registration, website claim, then feeds per
  country and language with prices in the feed currency and the tax of the feed country.
  Filters, attribute and category mapping with the Google product taxonomy, rules per
  feed, promotions, shipping, product statuses and reports. A new feed is a draft:
  nothing is sent to Google until you start sending.
- **Search Console and sitemap.** The property, daily search data, and a sitemap
  generated by the module in every shop language with hreflang, including Quince Blog
  posts when the blog is installed. The sitemap is rebuilt and submitted by cron and
  leaves out addresses that are inactive, redirected, `noindex` or missing.
- **Page speed.** Core Web Vitals of real visitors from the Chrome UX Report and lab
  tests of up to five pages with PageSpeed Insights.
- **Structured data.** A scan of what the theme and other modules already output, and
  JSON-LD types the module can add where they are missing, without doubling what is
  already on the page.
- **Google Customer Reviews.** The opt-in on the order confirmation page, shown only with
  the customer's consent, with delivery days per carrier so the survey never arrives
  before the parcel.
- **Scheduled tasks.** Five crons with their own recommended frequency (orders,
  products, statuses, sitemap, maintenance), or one address for everything.
- **Multistore.** Every setting belongs to a shop. Shops are set up one by one or several
  at once, can share one Google connection or use their own Google Cloud project, and a
  shop that is not set up gets nothing from the module.
- **Multilingual.** English base with a full Polish translation, on PrestaShop's standard
  translation system.

## What the module stores

- **The Google connection:** the OAuth client ID, and the client secret, refresh and
  access tokens, API key and Measurement Protocol secret encrypted with a key derived
  from the shop's `_COOKIE_KEY_`. None of them is ever written to the page, to a JSON
  response or to a log.
- **The order log:** for each order the reference, total, currency, the value of the
  `_ga` and session cookies at the time of the order, the consent state, the traffic
  source (UTM parameters, `gclid`, referrer) and what was sent to Google. Customer data
  sent for enhanced conversions is hashed with SHA-256 and only with consent.
- **The event log** (switchable, cleaned after 14 days), the module's API log (30 days),
  the Merchant Center feed state per product, Search Console daily totals, the last two
  page speed results and the sitemap files.

Uninstalling the module deletes all of it.

## What it does not do

- It does not delete anything at Google. Turning a service off, deleting a shop or
  uninstalling the module stops the module's work; data and settings in your Google
  accounts stay where they are.
- It does not remove key events in GA4 and does not change the link between GA4 and
  Google Ads.
- It does not read Google Ads data or use the Google Ads API. Google Ads gets
  conversions and remarketing through Tag Manager.
- It does not replace a consent banner. It reads the consent state from Quince CMP or
  from another tool's cookie.
- It does not use a shared Google app. Each shop creates its own Google Cloud project,
  so its data never passes through anyone else's servers.

## Requirements

| Requirement | Version |
|-------------|---------|
| PrestaShop  | 9.0.2 or newer (tested on 9.2.0 and 9.0.3) |
| PHP         | 8.4 (tested), 8.1 or newer required |
| PHP extensions | cURL, OpenSSL |
| HTTPS       | required by Google for the sign-in redirect and most services |
| Google      | a Google account with access to the services you connect, and a Google Cloud project (free) |
| Quince Engine | not required |

Quince Insight works on its own. Quince CMP (as the consent source) and Quince Blog (in
the sitemap and the page speed checks) are used when they are installed.

## Installation

The release ZIP already contains everything the module needs. Composer and the
command line are not required.

**From the back office**

1. Download the latest **`quince_insight.zip`** from the
   [**Releases**](https://github.com/quinceproject/quince_insight/releases) page.
2. In the back office go to **Modules → Module Manager → Upload a module** and
   choose the ZIP. PrestaShop installs it.

**By copying the files to the server**

1. Unpack the release ZIP. It contains a `quince_insight` folder.
2. Upload that folder to the `modules/` directory of the shop, for example by FTP.
3. In **Modules → Module Manager** find Quince Insight and click **Install**.

**From Quince Engine** *(coming soon)*

The module list in Quince Engine will install the module straight from its release,
without downloading anything by hand.

> ⚠️ **Do not** use the green **Code → Download ZIP** button on this page. That
> archive contains the source only and is **missing the `vendor/` folder**, so the
> module will not run. Always install from a
> [**Release**](https://github.com/quinceproject/quince_insight/releases).

In a multistore installation enable the module in every shop that should use it.

## Configuration

Open **Quince project → Quince Insight** in the back office menu, or click **Configure**
next to the module in the Module Manager. Until a shop is set up, this opens the setup
wizard:

1. **Welcome**, then **Shops** when PrestaShop runs more than one shop.
2. **Services.** Which Google services to connect.
3. **Google Cloud project.** Instructions with direct links to the right Google Cloud
   screens, the list of APIs to enable for the chosen services, and the redirect address
   to copy. Paste the client ID, the client secret and, for page speed, the API key.
4. **Google account.** Sign in with Google; the wizard shows which permissions were
   granted.
5. One step per chosen service: **Analytics, Google Ads, Tag Manager, Site
   verification, Merchant Center, Customer Reviews, Search Console**.
6. **Summary**, with the cron lines to add on the server.

After the wizard the sidebar holds the screens:

1. **Overview.** What needs attention, one card per service, the Google connection.
2. **Analytics.** Overview, traffic, funnel and the property.
3. **Events.** The container, the event list, consent, server-side sending, the order
   log, the event log and missing orders.
4. **Merchant Center.** Overview, products, what is sent, mapping, rules, promotions,
   shipping and reports, per feed.
5. **Search Console.** Overview and the sitemap.
6. **Page speed.** Real visitors and lab tests of key pages.
7. **Structured data.** What is on the shop, what the module can add, a preview.
8. **Settings.** The Google connection, shops, services, crons and log retention.
9. **Support.** System information and the changelog.

### Google Cloud setup in brief

1. In the Google Cloud console create a project (or use an existing one).
2. Enable the APIs listed in the wizard (for example Google Analytics Admin API, Google
   Analytics Data API, Tag Manager API, Merchant API, Google Search Console API, Site
   Verification API, PageSpeed Insights API, Chrome UX Report API).
3. Configure the OAuth consent screen and publish the app (status *In production*).
   While the app is in *Testing*, the Google sign-in expires after 7 days.
4. Create an OAuth client of type *Web application* and add the redirect address shown
   in the wizard: `{shop address}index.php?fc=module&module=quince_insight&controller=oauth`.
   Copy the client secret right away: Google shows it in full only once. A client that
   is not used for 6 months is deleted by Google.
5. For page speed create an API key.

### Scheduled tasks (cron)

**Settings → Cron** shows a ready line with the address and token of each shop (curl or
wget), the recommended frequency, the last run and a **Run now** button. Only the crons
needed by the enabled services are shown.

| Cron | What it does | Recommended |
|------|--------------|-------------|
| Orders | purchases and refunds to Analytics, missing orders | every 10 minutes |
| Products | product changes to Merchant Center | every 15 minutes |
| Statuses | product statuses, account issues, promotions | every 3 hours |
| Sitemap | sitemap rebuild and submission | once a day, at night |
| Maintenance | Search Console data, page speed, connection check, log clean-up | once a day |

Hosting with a limit on cron jobs can use one address for everything (`group=all`,
every 5 minutes); the module then runs each group no more often than its
recommendation.

## Architecture

- **`Core`** holds what every service shares: the Google connection and OAuth flow
  (`Core\Google`), a cURL client with retries and Google's quota rules, encrypted
  settings per shop in the module's own table, background jobs with a progress bar,
  the cron scheduler and the hook router.
- **`Service\*`** has one folder per service (Analytics, Events, TagManager, Merchant,
  MerchantTools, SearchConsole, PageSpeed, StructuredData, Verification). Each one
  declares its hooks, cron tasks, jobs, tables and wizard step.
- **Front controllers** `oauth` (Google sign-in return), `cron`, `sitemap` and `event`
  (the event log beacon, rate limited).
- **Symfony controllers and Twig** for the back office, with the module's own copy of the
  Quince panel styles, so it does not need Quince Engine.
- Google is called over plain REST with the module's own client; no Google client
  library is bundled.

## Development / building from source

This repository tracks **source only**. The `vendor/` directory is git-ignored, so a
`git clone` is **not** directly installable. **Start with `composer install`**.

```bash
git clone https://github.com/quinceproject/quince_insight.git
cd quince_insight
composer install
```

The folder must be called `quince_insight`, the same as the module. A clone of this
repository already has that name.

To build an installable archive, run
`php .github/scripts/build-package.php quince_insight <version> build` and zip the
`build/quince_insight` folder. Pushing a tag `vX.Y.Z` does this and publishes the
release.
